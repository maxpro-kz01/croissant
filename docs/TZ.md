# Техническое задание: веб-приложение «Croissant — cakes and coffee»

Версия 1.0 (черновик на согласование) · Заказчик: кофейня Croissant (Кызылорда) · Исполнитель: ИП MaxPro

## 1. Цель
Мобильное веб-приложение (PWA) с онлайн-меню. Гость выбирает блюда и оформляет заказ. Заказ сохраняется в базе и уходит в WhatsApp заведения. Приложение само определяет сценарий: гость в зале (по QR-коду стола) или клиент дома (доставка/самовывоз).

Ainur's Cakes в этот проект не входят, это отдельное приложение позже. Архитектуру делаем так, чтобы её можно было переиспользовать.

## 2. Роли
| Роль | Доступ |
|---|---|
| Гость | Меню, корзина, оформление заказа без регистрации |
| Официант/кассир | Живая доска заказов, смена статусов, смена и касса |
| Администратор | Всё вышеперечисленное, редактирование меню, баннеров, столов, QR-кодов, настроек, отчёты |

## 3. Сценарии заказа
1. **В зале.** QR на столе ведёт на `/?table=N`. Приложение показывает «Стол N», просит только имя (по желанию), комментарий и отправляет заказ. Адрес не нужен.
2. **Доставка.** Ссылка/QR без стола. Поля: имя, телефон, адрес (улица, дом, кв., ориентир), комментарий, способ оплаты, время (как можно скорее или на время). Показываются стоимость доставки и минимальная сумма заказа.
3. **Самовывоз.** Имя, телефон, время. Переключатель «Доставка / Самовывоз» на странице оформления.

Тип заказа (`dine_in`, `delivery`, `pickup`) сохраняется и влияет на текст в WhatsApp, на отчёты и на доску заказов.

## 4. Функции гостя
- Меню по категориям (кофе, десерты, выпечка, завтраки и др.), поиск, фото, описание, цена, вес.
- Модификаторы: размер, молоко, сироп, добавки (опции с наценкой).
- Корзина, изменение количества, комментарий к позиции и к заказу.
- Оформление и экран «Заказ принят» со статусом (новый, готовится, готов, выдан).
- Баннеры и акции, контакты, часы работы, ссылка на Instagram.
- Вне часов работы заказ блокируется с понятным сообщением.
- Язык: русский (казахский закладываем в структуру, включим по запросу).

## 5. Отправка в WhatsApp
- **Версия 1:** заказ записывается в БД, затем открывается `wa.me/<номер>?text=<заказ>` с готовым текстом: тип заказа, стол или адрес, позиции, сумма, комментарий, номер заказа. Гость нажимает «Отправить».
- Ограничение: при таком способе сообщение уходит только после нажатия гостем. Поэтому источником истины служит доска заказов в админке, WhatsApp служит уведомлением.
- **Версия 2 (по желанию):** WhatsApp Business Cloud API, чтобы сообщение приходило автоматически. Требует бизнес-аккаунт Meta.

## 6. Админ-панель
- Вход по логину и паролю (JWT, роли). Скрытый вход двойным тапом по логотипу сохраняем как удобный ярлык на страницу входа.
- **Живая доска заказов:** карточки по статусам, обновление в реальном времени (WebSocket/SSE), звуковой сигнал, фильтр по типу и столу. Видно, какие столы сейчас заказывают в зале.
- Меню: категории, позиции, фото, модификаторы, «нет в наличии», порядок, скидки.
- Баннеры и акции.
- Столы и QR-коды: создание столов, генерация и скачивание QR (PNG/PDF-лист для печати).
- Смены и касса: открытие/закрытие смены, начальная сумма, итог, расхождение.
- Отчёты: выручка по дням/неделям, по типам заказа, популярные позиции, средний чек; экспорт в CSV.
- Настройки: номер WhatsApp, часы работы, зоны и стоимость доставки, минимальная сумма.

## 7. Нефункциональные требования
- Mobile-first, быстрая загрузка (первый экран до 2 с на 4G), PWA с иконкой на экран.
- Дизайн по логотипу: тёмно-коричневый на светлом, минимализм, тонкие линии, фирменный лучистый круассан.
- Безопасность: хэширование паролей (bcrypt), валидация входных данных, rate limit на создание заказов, защита от XSS/SQL-инъекций, HTTPS.
- Резервное копирование БД, логирование, обработка ошибок.
- Персональные данные клиентов (телефон, адрес) хранятся только на нужный срок.

## 8. Архитектура и стек
- **Frontend:** React + TypeScript + Vite, React Router, Zustand, framer-motion, обычный CSS с токенами (без Tailwind).
- **Backend:** Node.js + Express + TypeScript, Zod, JWT, Socket.IO/SSE.
- **БД:** PostgreSQL, чистый SQL-миграции (pg), seed командой `npm run seed`.
- **Хостинг:** Render (web service + Postgres + static site) или VPS по выбору заказчика.
- **Тесты:** Vitest (unit), Supertest (API), Playwright (основные сценарии).
- **Качество:** ESLint, Prettier, Git, `.env.example`, README.

## 9. Модель данных (основное)
`Category`, `MenuItem`, `ModifierGroup`, `Modifier`, `Table`, `Order` (type, status, table_id, customer_name, phone, address, comment, total, payment_method), `OrderItem`, `Shift`, `CashEntry`, `Banner`, `User` (role), `Setting`.

## 10. API (кратко)
- `GET /api/menu` · `POST /api/orders` · `GET /api/orders/:id/status`
- `POST /api/auth/login` · `GET/PATCH /api/admin/orders` · `CRUD /api/admin/menu|categories|banners|tables`
- `POST /api/admin/shifts/open|close` · `GET /api/admin/reports`
- `GET /api/admin/tables/:id/qr`

## 11. Этапы и приёмка
1. Каркас проекта, БД, seed меню, дизайн-система.
2. Меню, корзина, оформление (зал/доставка/самовывоз), WhatsApp.
3. Админка: доска заказов в реальном времени, меню, столы и QR.
4. Смены, касса, отчёты, настройки.
5. Тесты, деплой, печать QR, инструкция для персонала.

**Приёмка:** гость со стола сканирует QR, оформляет заказ, заказ появляется на доске и в WhatsApp с номером стола; клиент вне заведения оформляет доставку с адресом; админ меняет меню и видит отчёт.

## 12. Допущения (прошу подтвердить)
- Онлайн-оплата включена: способы «наличные», «карта на месте», «Kaspi» (ссылка) и «онлайн». Сейчас онлайн работает через демо-провайдер; боевой эквайринг (Kaspi Pay / Halyk / CloudPayments) подключается адаптером после заключения договора. Статус оплаты обновляется вебхуком с HMAC-подписью.
- Меню, фото и цены предоставляет заказчик.
- Один филиал.
